# Figma → Code — agent instructions

## What This Is

A **design-system-first** Figma importer. Point it at a Figma file; it extracts that file's declared design language — variables, styles, type ramp, spacing, components — and serializes it into a portable **OpenDesign v1 rich package** at `design-systems/<slug>/`.

The Figma twin of [`../ai-website-cloner-template/`](../ai-website-cloner-template/). Both feed the **same** emitter through the **same** intermediate contract (`source/tokens.source.json`); only extraction differs.

**Status:** scaffolded 2026-07-24. Contracts and stubs only — no working code. Read [`docs/BUILD-PLAN.md`](docs/BUILD-PLAN.md) before writing any.

## Non-negotiables

1. **Never hardcode the token slot list.** Read OpenDesign's `TOKEN_SCHEMA` at build time (`--od-root`, default `../../../skills/open-design`). It is 56 slots across 4 layers today and is allowed to change.
2. **Never hand-edit derived files.** `design-tokens.json`, `tailwind-v4.css`, `components.manifest.json` are caches generated by OpenDesign's own renderers. Edit `tokens.source.json` or `components.html`, then re-emit.
3. **Never invent a token value.** Every entry in `tokens.source.json` carries a `confidence` (`high` | `derived` | `fallback`) and a `source` pointing at real evidence (variable path, style name, node id). An absent value is better than a guessed one — the emitter has schema fallbacks for exactly this.
4. **Budget Figma MCP calls.** The official MCP is rate-limited (see `docs/BUILD-PLAN.md` § Risk 1). Extraction must be call-frugal: one metadata pass, one variables pass, then targeted reads. Never loop the MCP over nodes.
5. **Acceptance is the guard, not a vibe.** A milestone is done when `validate-design-system.ts` passes — equivalent to `pnpm guard` + `pnpm typecheck` inside the OpenDesign repo.

## Commands

```bash
npx tsx scripts/extract-figma-tokens.ts --file <key> --brand <slug>
npx tsx scripts/emit-design-system.ts --brand <slug> --name "<Name>" --category "<Category>"
npx tsx scripts/validate-design-system.ts --brand <slug>
```

## Code style

- TypeScript, ESM, `node:` prefixed builtins, no `any`.
- Scripts are `npx tsx` tools, not app source — keep them dependency-light and single-purpose.
- 2-space indent, named exports.

## Repo facts that bite

- This project is **tracked directly by the notes repo** — unlike `ai-website-cloner-template`, it is *not* a git submodule. No separate origin, no submodule pointer to bump.
- Because it lives inside the notes repo, `--od-root`'s default relative path (`../../../skills/open-design`) resolves correctly. If this project is ever extracted to its own repo, that path breaks — pass `--od-root` explicitly.
- `design-systems/**` is emitted content and `scripts/**` is tsx tooling; keep both out of any app-level tsconfig/eslint program if one is added later (the cloner had to do exactly this to keep CI green).
