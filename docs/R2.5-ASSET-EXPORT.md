# R2.5 — targeted original IMAGE-fill export

**Status:** implementation and offline contract complete; live acceptance pending.

R2.5 closes asset gaps named by the frozen topology without recapturing the page. It
uses a distinct evidence contract because the historical `capture-manifest/v1` is immutable
and remains pinned to the runtime that produced it.

## Boundary

- `capture-figma.ts`, `raw/**`, screenshots, and the original manifest are not rewritten.
- The new exporter names every requested `nodeId` and zero-based image `paintIndex` on the
  command line. It never discovers a page, walks a subtree, changes the active page, or calls
  a write-oriented MCP tool.
- The exporter runs on the same pin as new captures (`R3_3_1_FORK`, `01ab491`, since
  2026-09-25, from its own worktree; it moved from `R3_2_1_FORK`, pinned since 2026-09-24,
  which itself shipped on `63e3055`, under which no export manifest was ever written), so
  one DEV plugin serves both passes. Before a Figma read it verifies the fork commit, server
  bundle, plugin files, relay, required schemas, and the connected server/plugin identity.
  Pass `--fork-root` with an isolated worktree at the pin.
- Each recovered source file remains private-local under `docs/research/<slug>/asset-exports/`.
  The bundle records byte hashes, the full image-paint placement data, source-capture hash, and
  `get_node_info` readings before and after the read. The observations must be canonically
  identical before the manifest is written.

## Run

```bash
npm run check:r2.5:asset-export

npm run export:image-fills -- \
  --channel <figma-channel> \
  --export-id <private-export-slug> \
  --out docs/research/<slug>/asset-exports/<export-slug> \
  --source-capture docs/research/<slug>/capture-manifest.json \
  --captured-by <operator> \
  --asset <asset-id>=<node-id>@<paint-index>
```

The relay and matching DEV plugin must already be running. A stale or absent plugin fails
before the first source-byte request. The output directory must be new and empty, which keeps
retries from silently overwriting prior evidence.

## Acceptance

The offline contract gate exercises the pin boundary, narrow tool fingerprint, evidence-path
uniqueness, and the no-mutation comparison. Live acceptance additionally requires the exact
source files and receipts to agree on their byte count and SHA-256, with the original node
observation unchanged after each export.

## Live acceptance (2026-09-26, Banco Lucrativo)

`export_image_fill` sends each original image as one unbounded base64 message; the relay is
`Bun.serve` with no `maxPayloadLength`, so Bun's 16 MiB default message cap applies. Two
live attempts (42 assets each, on two different channels) both hung on the first asset with
0 bytes written and are left as-is. `export_node_as_image` is bounded (a ~5.3 MB render
passed clean) and carried the whole pass instead, rendering each image-fill node as PNG
under a ≤3 MP budget scale rather than exporting original fill bytes.

Counts for this run, via `scripts/export-figma-nodes.ts`:

- SVG targets (`SVG@1`): 63 requested, 57 exported, 6 rejected by Figma. The 6 rejections
  were re-exported as budget-scaled PNG fallbacks in a separate bundle (6 of 6).
- Image-fill nodes (PNG, budget-scaled): 36 unique nodes, 32 rendered, 4 skipped (page-copy
  descendant guard).
- Composites (9 whole + 8 split children, PNG): the first batch failed at `join_channel`
  (`Not connected to Figma`) before any node was attempted. One retry into a fresh bundle
  exported 17 of 17. The failure is a latent start-up race rather than a plugin drop, because
  the relay stayed up and the retry needed no plugin relaunch: the capture and both exporters
  call `join_channel` as soon as the spawned server starts, without waiting for its relay socket.
- Published: 116 files under `src/assets/private/banco-lucrativo/`, 44,120,897 bytes total,
  with 0 ledger assets missing. `docs/research/banco-lucrativo/normalized/asset-map.json` sha256
  `85ce1adc7967be112d2f86a3df757000f50951195d588713bbc33f3f67c6b47c`.
